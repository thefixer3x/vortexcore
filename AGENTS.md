# Project rules
- Active AI interfaces call the Supabase `ai-router` function using user/assistant messages; a single contract avoids provider-specific response mismatches.
- AI branding uses the shared Lucide VortexAI icon and product-named routes; private upstream model identifiers stay server-side because integrations require their exact identifiers.
- Never change shared-table access policies without confirming intended access; this Supabase project serves multiple applications.
- Server Supabase clients use the shared key-aware factory with isolated auth state; opaque API keys go only in apikey and verified user JWTs remain in Authorization, so privileged operations preserve server identity without RLS workarounds.
- Endpoint and classification ownership is assigned by trusted services; organization access uses server-controlled app_metadata.org_id, not editable membership rows or user metadata, to prevent tenant spoofing.- VortexCore tables live in `app_vortexcore` behind `security_invoker` views in `public`; realtime subscriptions target `app_vortexcore` because views emit no change events.
- Admin/cockpit data lives in `control_room`, which has no anon/authenticated grants; the app reaches it only through server-only `public` views/functions called with the secret key, scoped to `app_id = 'vortexcore'`, so other apps' cockpit rows stay untouched.
- Plans and prices come from `vortex_pricing_tiers`; an admin price change creates a new Stripe price and keeps old ids in `previous_price_ids`, so existing subscribers keep resolving to their tier.
- The browser client ignores legacy JWT anon keys (disabled on this project) and falls back to the built-in publishable key, so a stale `.env` can't break sign-in.
- Bank statements: CSV is parsed deterministically (`_shared/statement-csv.ts`); PDFs are read with structured output through the Responses helper; imported rows carry `stmt:` references so re-uploads are skipped.
- `supabase/migrations/` is written only by the migration tool; `supabase/migrations-applied/` holds read-only reference copies of the live migration history (shared with other apps).
